# 共有ステージ

ピクあ！の共有ステージは、読み込んだキャラクター 1〜9 体を `.piqua` ファイルにして、Cloudflare R2 へ置き、URL を X などで渡す機能です。ゲーム内の投稿一覧やチャットはありません。

アップロード先が空のあいだは、端末への保存と、手元のファイルの読み込みだけが動きます。

## 2. Unity 側の動き

入口はバトルのステージ選択です。「共有ステージ」を押すと、作成と読み込みが出ます。

作成では、自分が読み込んだキャラクターだけを 1〜9 体選びます。ステージ名、投稿者名、コメント、メインカラー、背景を入れて、300 階のプレビューを見てからファイルを出します。出力した内容は、その時点のキャラクターの写しです。あとから育成しても、出したファイルは変わりません。同じステージを作り直すと、ステージ ID はそのままで更新番号だけ増えます。

ファイルの中は ZIP です。

- `manifest.json`：形式バージョン、ゲームバージョン、ファイル ID、ステージ ID、投稿者 ID、投稿者名、作成日時、更新日時、更新番号、内容ハッシュ
- `stage.json`：ステージ名、コメント、色、背景、キャラクター
- `characters/character_001.png` から最大 `character_009.png`

投稿者 ID は、この端末の初回利用時に作る UUID です。本人確認ではありません。セーブを消すと変わります。

自分の投稿者 ID と一致するファイルは読み込めません。ハッシュは破損と同一内容の確認用で、署名ではありません。

読み込みに成功するとセーブしてから演出を出します。演出はスキップできます。演出の途中でアプリを閉じても、登録自体は先に保存済みです。

戦闘は通常ステージの隣の別枠です。ステージ番号 8 で、ギャラリーの 7 には入れません。1〜299 階の敵の数はギャラリーと同じ増え方で、登録キャラから重複ありの抽選です。300 階は登録した全員が 1 体ずつ出ます。

敵レベルは「その階の基本レベル + そのステージで反映済みの星の数」で、上限は `max(30, 登録キャラの最低レベル)` です。出撃を押した時点で固定します。291〜300階を誰も倒れずにクリアすると星を1つ得て、レベル上限と合成上限が通常の星と同じだけ上がります。星を得るまでは、読み込み直しても敵レベルは変わりません。星を得たあとにそのステージを読み込むと、敵レベルが1段上がり、もう一度星を狙えます。得た星の数は、一覧と戦闘中の星の隣に出します。

ファイルを読み込んだキャラには、20000 から ID を振ります。50 個ごとの枠を順に置きます。同じ投稿者のキャラは、その投稿者の枠の続きに入ります。A の 3 体は 20000、20001、20002。次の B の 2 体は 20050、20051。もう一度 A を読んで、そのうち 2 体が新しい絵なら 20003、20004 です。1 人の新しい絵が 50 体を超えたら、末尾に次の 50 枠を足します。あいだの投稿者の ID は動きません。同じ投稿者の同じ絵は、ステージが違っても同じ ID です。

300 階をクリアするまでは仲間加入判定をしません。クリア後の再挑戦（201〜300 階）から、既存の LUK と OBS の加入確率を使います。加入したキャラは、読み込み時に振った ID の仲間になります。読み込み枠は使いません。所持の上限は仲間側で 500 です。

X への共有は Android の共有シートです。投稿し終えたかどうかはアプリから分からないので、戻ってきて「共有したので報酬を受け取る」を押す自己申告です。報酬は端末の日付で 1 日 1 回。登録キャラのサイズに対応する経験値玉を、キャラごとに 10 個。全ピクセルを 100 個です。

## 3. Worker API

ベース URL の末尾に `/` は付けません。

| メソッド | パス | 動き |
|---|---|---|
| `POST` | `/v1/files` | 本文が `.piqua` そのもの。`Content-Type: application/octet-stream` |
| `GET` | `/v1/files/{fileId}` | ファイル本体。`fileId` は小文字の UUID |
| `HEAD` | `/v1/files/{fileId}` | あれば 200、なければ 404 |
| `OPTIONS` | 上記 | 将来のサイト用の CORS |

成功は 200 または 201 です。アプリは返ってきた URL を使わず、自分の持っているベース URL とファイル ID からダウンロード URL を組み立てます。

失敗時の JSON は `{ "error": "理由" }` です。

受け付けないもの：

- 1MB を超えるファイル、展開後 2MB を超える中身、1 枚 256KB を超える PNG
- 1〜9 体以外、8 / 16 / 32 / 64 以外の画像、正方形でない画像
- UUID でない ID、必須項目の欠け、ステータスが 0〜1,000,000,000,000 の外
- パスに `..` が含まれる ZIP、暗号化 ZIP、展開しすぎる ZIP
- 内容ハッシュが一致しないファイル
- 同じファイル ID で中身が違う再アップロード（409）
- 同じ接続元から UTC の 1 日に 31 回目以降のアップロード（429、上限 30 回）

不正なファイルは R2 に置きません。秘密鍵はアプリにも Worker にも置きません。R2 は非公開で、外から直接は読めません。

## 4. R2 と Worker の設定

アカウントは [https://dash.cloudflare.com/](https://dash.cloudflare.com/) で作ります。

1. ログイン後、左の **R2 Object Storage** を開く。
2. 初めてなら、画面の案内に従って R2 を有効にする。支払い方法の登録を求められたら、それに従う。無料枠の範囲でも、アカウントに支払い方法が要ることがあります。
3. **Create bucket** を押す。
4. バケット名を `piqua-share` にする。場所は初期のままでよい。
5. 作成後、そのバケットの設定で公開アクセスをオンにしない。カスタムドメインも付けない。

Worker 側のバインド：

1. PC に Node.js を入れる。[https://nodejs.org/](https://nodejs.org/) の LTS でよい。
2. このプロジェクトの `Cloudflare/piqua-share` フォルダを、エクスプローラーのアドレス欄に `cmd` と打って開く。
3. 次を実行する。

```bat
npx wrangler login
npx wrangler deploy
```

4. ブラウザが開いたら、Cloudflare へのログインを許可する。
5. 成功すると、`https://piqua-share.<あなたのサブドメイン>.workers.dev` のような URL が出る。

環境変数と秘密情報は作りません。`wrangler.toml` の `SHARE_BUCKET` が、バケット `piqua-share` への通り道です。アプリに API トークンは入れません。

アップロード URL をゲームへ入れる：

1. Unity で `Assets/Scripts/Share/ShareStageConfig.cs` を開く。
2. `WorkerBaseUrl` の `""` を、上の URL に置き換える。末尾の `/` は付けない。

```csharp
public const string WorkerBaseUrl = "https://piqua-share.xxxx.workers.dev";
```

3. Unity に戻って、コンパイルが終わるまで待つ。

空のままだと「アップロード先が未設定です。端末への保存はできます。」と出ます。

## 5. Android 実機での確認

1. Unity の **File > Build Settings** で Android を選び、Development Build のままビルドする。
2. バトルのステージ選択で「共有ステージ」が出ることを見る。
3. 読み込み済みキャラで 1 体のステージを作り、端末へ保存する。拡張子は `.piqua`。
4. 一度一覧へ戻り、保存したファイルを読み込む。自分の投稿者 ID なので「自分のステージは読み込めません。」になる。
5. 9 体でもファイルが作れることを見る。
6. `WorkerBaseUrl` を入れたビルドでアップロードし、表示された URL を別の端末、またはセーブデータを消した状態で読み込む。
7. URL のファイル ID を 1 文字変えて、見つからない表示になることを見る。
8. 共有ボタンで共有シートが開き、X を選べること。戻って報酬ボタンを押し、同じ日の 2 回目は断られることを見る。
9. アプリを終了して開き直し、読み込んだステージが残っていることを見る。
10. 1〜10 階の敵がレベル 5 以上、300 階に登録人数だけ出ること。300 階クリア前は仲間が増えず、クリア後の再挑戦で加入判定があることを見る。

通常のステージ選択、ギャラリー、読み込みキャラの上限、レベル上限が、共有ステージを触る前と変わっていないことも見る。

## 6. 運用コストの目安

2026 年時点の Cloudflare 無料枠の目安です。料金表は変わるので、公開前にダッシュボードの R2 と Workers の表示を見てください。

- Workers：1 日 10 万リクエスト前後まで無料、の枠がある
- R2：保存 10GB、書き込みクラス 月 100 万回、読み出しクラス 月 1000 万回、までの無料枠がある。R2 からの外向け転送は無料、という説明が Cloudflare にある
- データベースは使っていない
- 1 ファイルは最大 1MB。30 人分のアップロードが毎日あっても、月の保存は 1GB に届かない
- 同じ接続元は 1 日 30 アップロードまで

無料枠を超えそうな通知が来たら、バケットの古いファイルを手動で消すか、上限を下げる。

## 7. ファイルの上限

| 項目 | 上限 |
|---|---|
| 圧縮ファイル | 1MB |
| 展開後の合計 | 2MB |
| PNG 1 枚 | 256KB。一辺 8、16、32、64 の正方形だけ |
| 登録キャラ | 1〜9 |
| 遊べる共有ステージ | 30。同じステージ ID の再読み込みは上書きで、クリア階は残す |
| 自分の下書き | 20 |
| 仲間 | 500。読み込みキャラの枠とは別 |
| ステージ名 | 20 文字 |
| 投稿者名 | 16 文字 |
| コメント | 80 文字 |

128 と 256 の画像は、ゲーム側が Coming Soon のあいだ共有にも入れません。
